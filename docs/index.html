03 / ОДИН УЧЕБНЫЙ ПРИМЕР

Загрузка ≠ принятый результат

Приняты четыре из восьми результатов. Но задачи имеют разный объём, поэтому в показателе используется вес исходного плана.

Принято из плана57,4%

124 из 216 плановых часов

План / факт принятых работ0,97×

124 часа оценки / 128 часов факта

Приёмка без замечаний74,2%

92 из 124 часов исходных оценок

Что можно решить: проверить источник переделок, уточнить входные требования и освободить время перегруженного специалиста.

Чего эти цифры не доказывают: качество работы человека, экономический эффект или причины изменения самоощущения.

06 / ПРЕДЛОЖЕНИЕ ДЛЯ СОГЛАСОВАНИЯ

Четыре недели, чтобы проверить пользу

Предлагаемый пилот

  1. Неделя 1. Согласовать состав, правила приёмки и одну тестовую группу проектов.
  2. Неделя 2. Проверить полноту факта и удобство импорта из Bitrix24.
  3. Неделя 3. Разобрать перегрузки, ожидания и переделки; выбрать улучшение.
  4. Неделя 4. Оценить качество данных и полезность решений, затем определить следующий шаг.

Что требуется от руководства

  • Назначить владельца пилота и того, кто подтверждает результаты.
  • Выделить 20–30 минут в неделю на разбор.
  • Согласовать правила доступа и добровольность самооценки.
  • Для совместной работы — сервер, авторизацию и резервирование.

Критерии успеха пилота: понятные обязательства, сопоставимый факт, подтверждённые результаты и проверяемые действия по итогам разбора. Экономический эффект пока не измерен.
