# ITO · Управление инженерным отделом

Презентационная сборка 0.6.1. Планирование ресурса, фактическое время, приёмка результатов и добровольная обратная связь команды.

**В этом пакете только вымышленные учебные данные.** Рабочие базы, реальные имена и проекты, исходные выгрузки, резервные копии и личные ответы сотрудников в пакет не входят.

**Первое действие:** откройте [`НАЧАТЬ_ЗДЕСЬ.txt`](НАЧАТЬ_ЗДЕСЬ.txt) — там весь порядок от распаковки до ссылки на GitHub Pages.

## Показ руководству — без установки

Откройте [`docs/index.html`](docs/index.html) двойным щелчком. Интернет и сервер не нужны. На странице есть сценарий показа, переходы в интерактивное приложение и кнопка печати / сохранения в PDF средствами браузера.

- [`docs/app.html`](docs/app.html) — интерактивное приложение с учебным отделом.
- [`docs/checkin.html`](docs/checkin.html) — демонстрация утренней / вечерней отметки и личной динамики.
- [`DEMO_GUIDE.md`](DEMO_GUIDE.md) — сценарий показа на 7–10 минут.

Демо использует только память страницы: не читает рабочие ключи localStorage, не обращается к API, не отправляет ответы и не сохраняет изменения после перезагрузки. Кнопка «Сбросить демо» возвращает исходный пример. Импорт рабочих файлов в демо отключён. Все графики состояния команды являются учебными.

## Публикация демонстрации на GitHub Pages

1. Создайте репозиторий и загрузите **содержимое этого пакета**, сохранив структуру папок. Не загружайте исходную рабочую папку приложения.
2. В репозитории откройте **Settings → Pages**.
3. Выберите **Deploy from a branch → main → /docs → Save**.
4. После завершения развёртывания GitHub покажет ссылку на сайт. Обычно это `https://USERNAME.github.io/REPOSITORY/`.

Для простого статического сайта отдельный workflow не нужен; в `docs` уже есть `.nojekyll`. Условия доступности Pages зависят от тарифа и видимости репозитория. Публикуемый сайт следует считать общедоступным.

Официальная инструкция: [настройка источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

**GitHub Pages размещает статическую презентацию.** Она не заменяет Python-сервер и общую базу ответов сотрудников. Публикация репозитория сама по себе не запускает серверную часть. Подробности — [`DEPLOYMENT.md`](DEPLOYMENT.md).

## Локальная серверная версия

Требуется Python 3.11+. На Windows запустите `app/start_windows.bat` либо выполните из корня пакета:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r app/requirements.txt
cd app
..\.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8010 --no-access-log
```

Откройте `http://127.0.0.1:8010`. Порт отличается от рабочего приложения. При первом запуске база создаётся из учебного примера. Изменения серверной версии сохраняются в `app/ito.sqlite3`; самоощущение — в `app/ito_wellbeing.sqlite3`. Личный дневник хранится в профиле браузера отдельно от сводок.

Это локальный прототип **без авторизации и ролей**. Командный доступ через интернет ещё нужно реализовать. Сервер по умолчанию слушает только `127.0.0.1`.

## Что реализовано

- Справочники команды, проектов и операций; назначения, отсутствия и недельный ресурс.
- Неизменяемый снимок плана; фактическое время; приёмка и возврат результатов.
- Раздельные показатели загрузки, принятого плана, план / факт и приёмки без замечаний.
- Предпросмотр импорта CSV/XLSX, отсечение повторов внешних ID, JSON-копии и CSV-отчёты.
- Личный дневник и добровольная отправка без имени; закрытые недельные сводки и динамика за период.

Следующие этапы: защищённое командное размещение, калибровка норм, прямая интеграция с Bitrix24, отдельная модель СМР / ПНР. Экономический эффект пока не измерен. Учебная загрузка и результаты не являются фактическими показателями какого-либо отдела.

## Повторная сборка

Сайт уже собран: `docs` можно публиковать сразу. Для повторной упаковки после изменений нужен только Python 3.11+, без установки библиотек и без доступа к GitHub.

```powershell
python tools/build.py --check
python tools/build.py
python tools/test_build.py
```

Первый вызов проверяет контрольные суммы исходного комплекта и ссылки. После осознанных правок запустите второй вызов: он пересчитает манифест и создаст `dist/ITO_GitHub_Pack_0.6.1.zip`. На Windows для сборки также есть `BUILD_RELEASE.bat`. Архив включает только перечисленные в `release-files.txt` файлы; новые исходники нужно явно добавить в список. Личные базы, временные папки и окружения сборщик не добавляет. Проверяйте содержание собственных правок перед публикацией: список файлов не умеет распознавать персональные сведения внутри текста.

## Проверки

JavaScript: Node.js 20+; Python: зависимости из `app/requirements-dev.txt`.

```powershell
node --test app/tests/core.test.js app/tests/wellbeing.test.js app/tests/wellbeing-analysis.test.js app/tests/demo.test.js
.venv\Scripts\python -m pip install -r app/requirements-dev.txt
cd app
..\.venv\Scripts\python -m unittest discover -s tests -p "test_*.py"
```

Тесты используют свои временные базы. Рабочие базы, `.env`, выгрузки и тестовые runtime-файлы исключены через `.gitignore` и не включены в архив.
