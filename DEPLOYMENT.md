# Два разных способа размещения

## Демонстрация

Папка `docs` — готовый статический сайт. Он работает из файла, с обычного веб-сервера и по пути `/repository/` на GitHub Pages. Все ссылки и ресурсы внутри демонстрации относительные. Сайт не делает запросов к API, не собирает реальные ответы и не использует browser storage для данных приложения.

Для показа с другого устройства в доверенной локальной среде можно отдельно разместить только `docs`. Для GitHub Pages выберите `main /docs` по инструкции в README. Репозиторий и сайт ещё не опубликованы этим пакетом.

## Настоящий командный пилот

GitHub хранит исходники; GitHub Pages не исполняет FastAPI. Для общей базы и отправки отметок потребуется отдельный сервер. Текущий `app` — основа локального пилота, не готовое интернет-развёртывание.

До командного запуска нужно реализовать и проверить:

- Идентификацию и роли: руководитель, сотрудник, администратор; запрет сотрудникам читать или менять общий `/api/state` без полномочий.
- Отдельные правила доступа к дневнику и общей сводке; отсутствие связки личных отметок с KPI и кадровыми решениями.
- HTTPS, ограничение запросов, управление сессиями и защита изменяющих запросов.
- Постоянные тома для двух баз, резервное копирование и восстановление из копии; запрет статической выдачи баз и резервных копий.
- Правила технических журналов: не записывать токены отметок и тело ответов; явно объяснить, какие инфраструктурные сведения доступны администратору.
- Сроки хранения и необходимые правовые основания обработки; ответственного за данные.

После этого можно выбирать хостинг и размещать подготовленную серверную версию. Данный архив не содержит учётной записи хостинга, домена, ключей, сертификатов или настроенных сервисов.
